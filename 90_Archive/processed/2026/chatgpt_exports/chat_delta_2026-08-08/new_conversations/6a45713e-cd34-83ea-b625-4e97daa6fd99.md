你的计算：

```text
1 / 128e9 = 7.8125 ps
```

**数学没错，但用于 PCIe 7.0 的“PAM4 waveform UI”时不对。** 这就是标准术语的坑，专门用来折磨工程师，像把香蕉皮铺在公式下面。🙃

PCI-SIG 对 PCIe 7.0 的官方说法是 **128.0 GT/s raw bit rate**，并且使用 **PAM4** signaling；PCI-SIG 也说明 PCIe 7.0 的 Nyquist frequency 是 **32 GHz**。citeturn338534search11turn338534search4

关键区别是：

| 概念 | PCIe 7.0 数值 | 说明 |
|---|---:|---|
| Raw transfer / raw bit rate | 128 GT/s ≈ 128 Gb/s/lane | 每 lane 原始传输比特率 |
| PAM4 每 symbol 携带 | 2 bits/symbol | 4 个电平表示 2 bit |
| Symbol rate / Baud rate | 64 Gbaud | `128 Gb/s / 2` |
| **PAM4 symbol UI** | **15.625 ps** | `1 / 64e9` |
| Bit-equivalent UI | 7.8125 ps | `1 / 128e9`，不是模拟波形 symbol UI |
| Nyquist frequency | 32 GHz | `64 Gbaud / 2` |

所以正确写法应是：

```text
PCIe 7.0: 128 GT/s raw bit rate

PAM4: 2 bits / symbol

Symbol rate = 128e9 / 2
            = 64 Gbaud

PAM4 symbol UI = 1 / 64e9
               = 15.625 ps
```

你原来的：

```text
UI = 1 / 128e9 = 7.8125 ps
```

更准确地说是 **bit-equivalent UI**，不是 PAM4 眼图、CDR、采样时钟意义上的 **symbol UI**。

一句话记住：

> **PCIe 7.0 的 128 GT/s 是 raw bit rate；因为是 PAM4，所以真正的 symbol UI 是 15.625 ps，不是 7.8125 ps。**

对 SerDes / clocking 来说，通常你关心的是：

```text
Symbol rate = 64 Gbaud
UI = 15.625 ps
Nyquist = 32 GHz
```
