## 1.1 Spec Matrix 的真正作用：把“系统能否工作”翻译成“电路该怎么设计”

这段话的核心不是“做一张更详细的表”，而是建立一条**可计算、可分配、可验证、可追责的规格翻译链**：

\[
\boxed{
\text{系统性能要求}
\rightarrow
\text{观测节点与测量条件}
\rightarrow
\text{噪声/抖动预算}
\rightarrow
\text{模块级指标}
\rightarrow
\text{电路参数}
\rightarrow
\text{晶体管与版图约束}
}
\]

ISSCC 2024 Session 7.3 的论文确实是一款 3 nm FinFET、224 Gb/s、面向 40 dB 插损信道的完整收发器，论文明确涵盖 RX/TX 及相关 clock paths。因此，拿它讨论“PLL core 指标”和“endpoint clock 指标”之间的区别是合适的。citeturn219504search5turn982022search0

# 一、为什么普通“需求表”不够

一个普通需求表可能只有：

| Spec | Target | Owner | Status |
|---|---:|---|---|
| TX jitter | < 55 fs RMS | PLL | Open |

这张表几乎不能指导设计，因为它没有回答以下问题：

- 55 fs 是在哪个节点测量？
- 是 PLL core 输出，还是 TX serializer 最终采样边沿？
- 是 raw jitter，还是经过 4 MHz clock recovery filter 后的 residual jitter？
- 积分频率范围是什么？
- 包不包含 reference spur、fractional spur、supply spur？
- 包不包含 clock distribution、phase interpolator、ILO 和 local CCU？
- 55 fs 是芯片本征指标，还是包含仪器噪声底后的测量值？
- 是 typical，还是全 PVT、全 mismatch、全供电噪声条件？
- 是单个 lane，还是 shared CMU 驱动全部 lanes 时？
- 是静态 phase error、随机 jitter，还是确定性周期抖动？

如果这些没有定义，那么“55 fs”只是一个带单位的愿望。

真正的 Spec Compliance Matrix 至少同时承担四项任务：

1. **语义翻译**：系统指标到底是什么意思。
2. **预算分解**：哪些模块各自允许贡献多少。
3. **设计反推**：这些预算对应哪些电路参数。
4. **验证闭环**：最终用什么 testbench、?

# 从 BER 到晶体管参数的完整翻译链

先把最容易被管理层和某些“系统专家”故意模糊的事实说清楚：

\[
\boxed{\mathrm{BER}\ \not\Rightarrow\ W/L}
\]

BER 与晶体管尺寸之间不存在一步到位的公式。真正的翻译过程是：

\[
\boxed{
\begin{aligned}
&\text{Post-FEC BER}\\
&\Downarrow\\
&\text{Pre-FEC BER}\\
&\Downarrow\\
&Q\text{-factor / SNR}\\
&\Downarrow\\
&\text{垂直眼高与水平眼宽}\\
&\Downarrow\\
&\text{噪声、抖动、ISI、失调预算}\\
&\Downarrow\\
&\text{AFE、ADC/Slicer、CDR、DFE、TX Spec}\\
&\Downarrow\\
&g_m,\ r_o,\ C,\ V_{\mathrm{ov}},\ I_D,\ f_T\\
&\Downarrow\\
&L,\ W,\ \text{finger 数、偏置、电流密度}
\end{aligned}}
\]

下面用一个**通用 224 Gb/s PAM4 接收机**作为完整算例。对应符号率为：

\[
R_s=\frac{224\ \mathrm{Gb/s}}{2}=112\ \mathrm{GBaud}
\]

\[
UI=\frac{1}{112\ \mathrm{GHz}}=8.929\ \mathrm{ps}
\]

这个速率属于 OIF CEI-224G 所覆盖的速率等级，但下面是设计方法示例，不代表某一标准的合规参数。citeturn136095search0

## 一、系统 BER 如何翻译成电路 BER

### 1. Post-FEC BER 不能直接拿来设计模拟前端

假设系统要求：

\[
BER_{\mathrm{post-FEC}}\leq 10^{-15}
\]

不能因此要求模拟接收机直接做到：

\[
BER_{\mathrm{analog}}\leq 10^{-15}
\]

否则你会设计出一台耗电像暖炉、面积像停车场、最终仍然过不了 PVT 的怪物。

正确关系是：

\[
BER_{\mathrm{post}}
=
\mathcal{F}_{\mathrm{FEC}}
\left(
BER_{\mathrm{pre}},
\text{burst distribution},
\text{error correlation},
\text{LLR quality}
\right)
\]

其中 \(\mathcal{F}_{\mathrm{FEC}}\) 是 FEC waterfall 曲线。

1.1 Spec Matrix 的真正作用：把系统语言翻译成电路语言
Spec Compliance Matrix 不是需求列表，而是一台“翻译机”。系统团队说的是 BER、UI、eye margin、protocol mask、CDR tracking；PLL设计工程师真正能调的是 fPFD、N、loop bandwidth、ICP、KVCO/KDCO、VCO range、divider topology、DTC/TDC resolution、phase rotator LSB、supply isolation 和 calibration policy。Matrix 的价值就在于把这两种语言连接起来。
一个合格的 matrix 行不应该只写“TX jitter < 55fs”。它至少要写清楚：这是哪个 mode、哪个 node、raw 还是 CDR-filtered、积分带宽是多少、是否包含 spur、是否包含 measurement floor、是否是 shared CMU 输出还是 TX endpoint、是否经过 TX/RX CCU、是否对应 ISSCC 2024 Session 7.3 Synopsys 224Gb/s 3pJ/b 40dB insertion-loss transceiver 里的 90fs 1/8-rate clock 或 55fs full-rate TX clock with 4MHz CDR。
设计实例：假设系统给出 224Gb/s PAM4 mode，目标是 TX endpoint clock RMS jitter 小于 55fs，条件是 4MHz CDR filter 后测量。这个需求不能直接交给 PLL core。它要先拆成 shared CMU raw jitter、1/8-rate distribution jitter、TX CCU residual、8-stage ILO residual、phase shifter 14fs step quantization、phase rotator 1/128 UI residual、TDC/background servo update noise 和 measurement margin。若只把 55fs 写给PLL，PLL团队会过度优化core noise，而真正失败点可能在local CCU或endpoint phase control。
设计要点：每条spec必须同时包含系统语义和电路语义。系统语义回答“为什么要这个指标”，电路语义回答“哪个电路参数会影响它”。没有这两层，spec matrix只能用于会议汇报，不能指导设计。
经验：刚开始建 matrix 时，不要追求表格漂亮。先把每一条关键指标从系统要求一路追到电路旋钮，哪怕文字长一点也值得。等?

## 为什么第一条公式出现很多等号

你当前源文件里很可能是：

```latex
\sigma_{\mathrm{total}}
========================
\sqrt{...}
```

正确的源码只能有一个：

```latex
\sigma_{\mathrm{total}}
=
\sqrt{...}
```

所以公式渲染器没有“自动拉长等号”，它只是忠实展示了文件中那一串灾难性的等号。
