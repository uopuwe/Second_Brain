# 从 PLL Spec 到 Tapeout：完整设计与验证流程

## 0. 首先建立正确认识

PLL 不是简单的：

\[
PFD+CP+Loop\ Filter+VCO+Divider
\]

真正可 tapeout 的 PLL 是一个同时涉及以下问题的闭环系统：

- 控制理论
- 相位噪声与时钟抖动
- 非线性锁定过程
- 模拟电路噪声
- 数字校准
- 电源和衬底耦合
- 高频时钟分频和分配
- 版图寄生
- 封装和芯片电源完整性
- AMS 顶层集成
- 测试与 silicon bring-up

一个 PLL 项目的正确主线是：

\[
\boxed{
Spec
\rightarrow
Clock\ System
\rightarrow
Jitter\ Budget
\rightarrow
Architecture
\rightarrow
Loop\ Model
\rightarrow
Circuit
\rightarrow
Verification
\rightarrow
Layout
\rightarrow
PEX
\rightarrow
Signoff
\rightarrow
Silicon
}
\]

最常见的新手错误是老板说：

> 输出 10 GHz，RMS jitter 小于 200 fs。

然后工程师立即开始设计一个 10 GHz LC VCO。

但在开始画 VCO 前，你必须先知道：

- 200 fs 的积分频率范围是什么？
- SSC 开还是关？
- 输出在哪里测量？
- 包不包括 clock buffer？
- 包不包括参考时钟？
- 是 random jitter 还是 total jitter？
- 哪些 phase-noise offset 最重要？
- reference spur 和 fractional spur 要求是什么？
- PLL 为 CDR、TX serializer、ADC clock 还是通用 SoC clock 服务？

否则所谓“200 fs”只是一串看起来很专业的数字。

## 1. 理解并澄清系统 Spec

首先确认：

- ADC 分辨率、采样率、输入带宽
- 输入幅度、共模和接口形式
- SNDR、SNR、SFDR、ENOB
- INL、DNL、offset、gain error
- 功耗、面积、电源、电压和温度范围
- latency、启动时间和工作模式
- 是否允许 calibration
- 哪些指标是 typical，哪些必须保证

输出：

- Spec clarification 文档
- Spec compliance matrix
- 尚未确定的问题和风险清单

核心任务是避免老板说“12 bit”，你就天真地以为是 12-bit ENOB。

---

## 2. 选择 ADC 架构

根据速度、精度、功耗和面积选择：

- SAR
- Pipeline
- Pipelined-SAR
- Time-interleaved SAR
- Flash
- Delta-Sigma

比较：

- 是否能达到采样率
- 功耗是否合理
- 模拟复杂度
- 是否需要放大器
- 是否需要通道交织
- calibration 复杂度
- PVT 和 mismatch 风险

输出：

- 架构框图
- 架构 trade-off
- 初步功耗、面积和速度估计

---

## 3. 建立误差预算

把系统指标分解给各模块：

- 量化噪声
- 采样热噪声
- 比较器噪声
- 时钟 jitter
- 电容或电阻 mismatch
- 建立误差
- reference noise 和 settling
- 开关非线性
- 放大器增益和线性误差
- 电源和数字耦合

同时建立：

- noise budget
- linearity budget
- timing budget
- power budget
- mismatch budget

输出：

- 顶层 error-budget 表
- 每个电路模块的 derived specs

---

## 4. 建立行为级模型

在晶体管设计之前建立：

- 理想 ADC 模型
- 含噪声、失配、jitter 和 settling 的非理想模型
- calibration 模型
- 输出编码和 latency 模型

常用工具：

- Python
- MATLAB
- Verilog-A
- SystemVerilog real-number model

验证：

- 架构是否理论可行
- 各误差对 SNDR、INL、DNL 的影响
- calibration 是否能收?

# PLL 项目中 Analog and Mixed-Signal Engineer 的必要设计步骤

## 1. 理解并澄清 PLL 系统规格

首先确认 PLL 的系统用途和边界条件：

- 输出频率范围
- 参考时钟频率和质量
- Integer-N 或 Fractional-N
- 相位噪声指标
- RMS jitter 及积分频率范围
- Reference spur 和 fractional spur
- 锁定时间
- 输出 duty cycle、摆幅和负载
- 电源、电压、温度、功耗和面积
- SSC、校准、测试和 debug 要求
- 指标测量位置，是 VCO 输出、PLL macro 输出还是 clock-tree endpoint

输出：

- Spec clarification
- Spec compliance matrix
- Open issues 和风险清单

最重要的是明确每条指标的测试条件。只写“jitter < 200 fs”而不写积分范围，基本等于没写。

---

## 2. 选择 PLL 架构

根据频率、jitter、spur、功耗、面积和调谐范围选择：

- Integer-N Charge-Pump PLL
- Fractional-N PLL
- LC-VCO PLL
- Ring-VCO PLL
- Sub-Sampling PLL
- ADPLL
- 必要时加入 frequency calibration、SSC 或多相输出

需要比较：

- 相位噪声能力
- tuning range
- 锁定速度
- spur 风险
- 数字校准复杂度
- PVT 鲁棒性
- 版图和面积代价
- 电源敏感度

输出：

- 架构框图
- Frequency plan
- 架构 trade-off
- 主要风险和备选方案

---

## 3. 建立频率计划和环路参数

确定：

- Reference frequency
- 输出频率
- 分频比范围
- VCO 频率范围
- 是否需要 prescaler
- Fractional 分频字
- SSC 调制范围
- coarse/fine tuning 分配

同时初步确定：

- Loop bandwidth
- Phase margin
- Charge-pump current
- VCO gain
- Loop-filter 参?

# 从 PLL Spec 到 Tapeout：Analog and Mixed-Signal Engineer 完整设计流程

## 1. PLL 项目的整体工程流程

一个可 tapeout 的 PLL 项目，不只是设计 VCO、PFD 和 Charge Pump，而是完成以下闭环：

\[
\boxed{
\text{Spec}
\rightarrow
\text{Architecture}
\rightarrow
\text{Loop Modeling}
\rightarrow
\text{Noise Budget}
\rightarrow
\text{Circuit Design}
\rightarrow
\text{Verification}
\rightarrow
\text{Layout}
\rightarrow
\text{PEX}
\rightarrow
\text{Signoff}
\rightarrow
\text{Silicon}
}
\]

PLL 系统一般包括：

- Reference Clock Receiver
- Phase-Frequency Detector，PFD
- Charge Pump，CP
- Loop Filter，LF
- Voltage-Controlled Oscillator，VCO
- Divider 或 Multi-Modulus Divider
- Frequency Calibration
- Lock Detector
- Fractional-N Delta-Sigma Modulator
- Spread-Spectrum Clock Generator
- Bias、LDO 和 Reference Circuits
- Output Clock Buffer
- Digital Control、Registers 和 DFT

# 从 ADC Spec 到 Tapeout：大型芯片公司级完整设计流程

## 0. 先建立正确认识：ADC 不是一个模拟电路，而是一套转换系统

一个真正可 tapeout 的 ADC，至少包含：

1. 模拟输入与采样网络
2. 量化核心
3. 比较器或子 ADC
4. 参考电压网络
5. 时钟产生与分配
6. 偏置、电源和共模产生
7. 数字控制逻辑
8. 数字纠错或校准
9. 输出接口
10. 测试模式与 DFT
11. 版图、电源完整性和可靠性设计
12. 行为模型、晶体管级 testbench 和后仿真环境
13. 芯片测试、评估板和量产 ATE 方案

新手最常见的误区是：

> 老板要求 12 bit，于是开始设计一个 12 bit CDAC。

这是顺序反了。

正确顺序是：

> 系统 spec → 测试条件 → 内部误差预算 → 架构选择 → 行为模型 → 电路指标 → 晶体管设计 → 集成验证 → 版图 → post-layout signoff → tapeout。

北美大型公司的重点不是“你有没有画出电路”，而是：

> 你是否能够用可重复、可追踪的数据证明，这个设计在规定的 PVT、失配、寄生、供电、时钟和使用条件下满足 spec。

# 第一阶段：读懂老板给你的 ADC Spec

## 1. 不要直接相信 spec 表格

客户、系统工程师或老板给出的 spec 往往是不完整的，甚至互相矛盾。

例如：

- Resolution：12 bit
- Sampling rate：100 MS/s
- SNDR：65 dB
- Input bandwidth：200 MHz
- Power：10 mW
- Supply：1.0 V
- No calibration
- All PVT guaranteed

每一项单独看都挺正常，合起来可能已经在策划一次悲壮的失败。

必须先建立一份 **Spec Compliance Matrix**。

建议至少包含以下列：

| 字段 | 内容 |
|---|---|
| Spec ID | 唯一编号，如 ADC_AC_001 |
| Category | DC、AC、时钟、电源、接口、可靠性等 |
| External requirement | 老板或客户原始要求 |
| Conditions | fs、fin、输入幅度、温度、电源、负载、模式 |
